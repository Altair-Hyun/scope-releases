## Features

### Catalog
- **Checkbox multi-select** with bulk actions (folder move, kubeconfig export)
- **Kubeconfig YAML export**: merge and download selected clusters' kubeconfig
- **Offline distro detection**: EKS, GKE, AKS, DigitalOcean, Alibaba, Huawei, Tencent, NCloud, OpenShift without cluster connection
- **Cluster API (CAPI)** management cluster detection
- **Duplicate cluster deduplication** across multiple kubeconfig files
- **Column resize** via drag on table headers
- **N-level nested folders** in hotbar and catalog

### Helm Charts
- **Refresh button** and repository update caching
- **Parallel loading** for chart README and versions

### v1.3.23 — 2026-11-27

**추가**
- 카탈로그에서 여러 클러스터를 체크한 뒤 아래 작업 막대의 삭제 버튼으로 kubeconfig 에서 한 번에 지울 수 있습니다. 확인 창은 파일마다 지울 context 수를 보여 주고, 지우는 것 중에 그 파일의 현재 context 가 있으면 새 현재 context 를 고르게 합니다. 클러스터가 아닌 항목(웹 링크 등)은 건너뛰고 몇 개를 건너뛰는지 알려 줍니다.
- 클러스터를 kubeconfig 에서 지우기 직전에 원래 파일을 앱 데이터 폴더의 kubeconfig-backups 아래 시각별 폴더에 복사해 둡니다. 삭제가 끝나면 백업 위치를 알려 줍니다. 한 개씩 지울 때도 같습니다.
**변경**
- Windows·Linux 트레이 아이콘을 어두운 둥근 사각형 위 흰 S 로 바꿨습니다. 업데이트 알림 배지에도 어두운 원 바탕을 깔아, 밝은 작업 표시줄에서도 아이콘과 배지 기호가 잘 보입니다. macOS 메뉴 막대 아이콘은 그대로입니다.
- 클러스터를 kubeconfig 에서 지울 때, 지운 context 만 쓰던 cluster·user 항목도 함께 지웁니다. 남은 다른 context 가 쓰는 항목은 그대로 둡니다.
**수정**
- 카탈로그 목록을 연 뒤 항목을 체크하면 아래에 나오는 작업 막대가 화면 밖으로 밀려 일부만 보이던 문제를 고쳤습니다. 이제 막대가 나타나면 목록이 그만큼 줄어듭니다.
- 창을 줄여도 파드·디플로이먼트 같은 리소스 목록이 따라 줄지 않아 아래쪽 행이 잘리던 문제를 고쳤습니다.
- 카탈로그에서 항목을 체크하면 오른쪽 아래에 뜨던, 눌러도 아무 일도 하지 않던 삭제(−) 버튼을 없앴습니다.
- 어두운 테마에서 클러스터 삭제 확인 창의 안내 문구가 흰 바탕에 흰 글자로 보이지 않던 문제를 고쳤습니다.
- kubeconfig 파일을 옮기거나 새로 만든 뒤에도 예전 파일을 읽어 "No valid context object" 오류로 클러스터에 연결되지 않던 문제를 고쳤습니다. 앱에서 클러스터를 지울 때도 지금 쓰는 kubeconfig 파일만 고칩니다.

### v1.3.22 — 2026-11-26

**변경**
- 클러스터에서 받은 리소스마다 붙어 있던, 화면에 쓰지 않는 필드 관리 기록(managedFields)을 보관하지 않습니다. 리소스가 많을 때 앱이 쓰는 메모리가 줄었습니다.
- 큰 목록을 500개씩 나눠 받습니다. 리소스가 아주 많은 클러스터에서 목록을 불러올 때 화면이 한 번에 오래 멈추지 않습니다.
- 앱이 클러스터와 주고받는 연결을 재사용해, 요청마다 새 보안 연결을 맺지 않습니다. 클러스터를 열고 화면이 뜨기까지가 빨라졌습니다.
- 클러스터 프록시에 닿지 못하면 같은 요청을 여러 번 다시 보내지 않고 바로 오류를 알립니다.
- 클러스터 인증을 맡는 프록시를 Scope 전용 scope-k8s-proxy 로 바꿨습니다. 최신 쿠버네티스 클라이언트로 다시 빌드했고, 앱을 만들 때 내려받는 프록시 파일의 체크섬도 확인합니다.
- 남기지 않을 상세 로그를 미리 버리고, 클러스터 응답 전체 대신 크기만 로그에 남깁니다. 큰 목록을 불러올 때 화면이 덜 멈추고 로그 파일이 덜 커집니다.
- 노드 상세를 열 때 클러스터의 모든 파드를 두 번 받아 오던 것을 한 번으로 줄였습니다. 파드 화면처럼 이미 파드를 받고 있는 화면 위에서 열면 다시 받지 않습니다. 네임스페이스를 일부만 골랐을 때도 노드의 모든 파드를 보여 주고 바뀌는 대로 갱신합니다.
- 터미널 출력이 많을 때 출력마다 저장소에 쓰던 일을 없앴습니다. 마지막 출력은 화면을 새로 고치기 직전에 한 번만 저장하고, 닫은 터미널 탭의 저장값은 지웁니다.
- 메트릭을 보여 줄 때 Prometheus 위치를 한 번만 찾고 기억합니다. 화면이 메트릭을 새로 받을 때마다 클러스터 전체 서비스를 다시 뒤지지 않습니다. Prometheus 가 없는 클러스터도 다시 연결하거나 Prometheus 설정을 바꿀 때만 다시 찾습니다.
- Applications 화면을 열 때 워크로드·서비스·설정 등 18 가지 자원을 두 번씩 받아 오던 것을 한 번으로 줄였습니다. 네임스페이스가 새로 생기거나 지워질 때 이 자원들을 모두 다시 받지도 않습니다.
- 서비스 상세와 로그 탭이 목록 화면이 이미 받고 있는 네임스페이스의 데이터를 다시 받지 않습니다.
- Applications 화면에서 앱을 체크하거나 펼치거나 배포 초안을 입력할 때마다 모든 앱 정보를 처음부터 다시 계산하던 것을 없앴습니다. 클러스터 자원이 바뀔 때만 다시 계산해서 화면이 덜 멈춥니다.
- 파드 상세에서 환경변수가 같은 ConfigMap 이나 Secret 을 여러 번 참조해도 한 번만 받아 옵니다. Job·CronJob·Ingress 같은 화면을 처음 열 때 하는 API 버전 확인도 네임스페이스 수와 상관없이 한 번만 합니다.
- 클러스터를 열 때 권한 확인, 네임스페이스 목록, API 목록 조회를 차례로 기다리지 않고 한꺼번에 보냅니다. 연결 화면의 "권한 확인" 단계가 짧아졌습니다.
- 클러스터 전체 목록 권한이 없는 사용자는 연결할 때 네임스페이스마다 권한을 한 번 묻고, 15분마다 하는 갱신에서는 새로 생긴 네임스페이스만 묻습니다. 네임스페이스가 많은 클러스터에서 연결 중 쌓이던 권한 조회가 줄어듭니다. 권한이 바뀐 것을 메뉴에 반영하려면 다시 연결합니다.
- 다른 클러스터나 카탈로그로 옮겨 보이지 않게 된 클러스터 화면은 메트릭을 주기적으로 다시 받지 않습니다. 그 화면으로 돌아오면 바로 새로 받습니다.
- 목록 화면에서 상세를 열거나 행을 체크할 때마다 표 전체를 다시 정렬하던 것을 없앴습니다. 항목이나 정렬 기준이 바뀔 때만 다시 정렬해서 큰 목록이 덜 멈춥니다.
- 네임스페이스 선택을 바꾸면 더하거나 뺀 네임스페이스만 새로 받거나 멈춥니다. 이미 보고 있던 네임스페이스는 다시 받지 않습니다.
- 목록의 행마다 붙은 메뉴(⋮)가 닫혀 있을 때도 창의 클릭·스크롤 등을 지켜보던 것을 없앴습니다. 메뉴가 열려 있는 동안만 지켜봐서, 행이 많은 목록에서 클릭하거나 스크롤할 때 할 일이 줄었습니다.
- 클러스터 상태처럼 카탈로그 항목 하나가 바뀌면 그 항목만 각 화면에 보냅니다. 전에는 카탈로그 전체를 모든 화면에 다시 보내고 모든 항목을 다시 그렸습니다. 클러스터 화면을 열 때도 그 화면에만 카탈로그를 보냅니다.
- 이벤트 화면이 이벤트가 갱신될 때마다 전체 목록을 같은 기준으로 두 번 정렬하던 것을 한 번으로 줄였습니다.
- 클러스터를 열 때 API 목록을 그룹마다 따로 묻지 않고 한 번에 받습니다(쿠버네티스 1.30 이상). 연결할 때와 15분마다 하는 갱신에서 클러스터로 가는 요청이 크게 줄고, 연결이 조금 더 빨라집니다. 더 오래된 클러스터는 지금처럼 그룹마다 묻습니다.
- 클러스터 변화가 한꺼번에 많이 들어올 때 목록에 반영하는 일이 가벼워졌습니다. 항목을 찾을 때 목록 전체를 훑지 않습니다.
- 클러스터 개요의 메트릭을 노드가 상태를 보고할 때마다 다시 받지 않습니다. 1분마다, 그리고 노드가 더해지거나 빠질 때만 받습니다.
- 로그 탭이 10초마다 새 로그를 확인할 때 이미 받은 줄 전체를 다시 처리하지 않고 새 줄만 덧붙입니다. 타임스탬프를 켜도 화면에 보이는 줄만 시간을 바꿔 보여 주어, 긴 로그를 열어 두어도 덜 멈춥니다. 닫은 로그 탭이 받아 둔 로그는 메모리에서 지웁니다.
- 앱 안의 화면들에 보내는 알림이 화면마다 한 번만 갑니다. 기본 화면이 같은 알림을 두 번 받던 것과, 클러스터 화면을 새로 고치거나 다시 열 때마다 알림 대상이 쌓이던 것을 고쳤습니다.
- 네임스페이스를 많이 고른 상태에서 목록을 고른 네임스페이스로 거르는 일이 가벼워졌습니다.
- 목록에서 항목 하나가 바뀌면 그 행만 다시 그립니다. 전에는 보이는 모든 행이 각자 목록 전체를 뒤져 자기 항목을 찾고 다시 그렸습니다.
- 설정·핫바·클러스터 목록을 저장할 때 항목마다 따로 파일을 쓰지 않고 한 번에 씁니다. 저장하는 동안 앱이 멈추는 시간이 줄었습니다.
- 15분마다 클러스터 정보를 갱신할 때 같은 버전 요청을 세 번 보내지 않고 한 번만 보냅니다. 노드 수를 셀 때도 노드 정보 전체를 받지 않습니다.
- 워크로드 개요와 워크로드 상세가 워크로드마다 모든 파드를 훑지 않습니다. 파드와 워크로드가 많은 클러스터에서 개요가 가벼워졌습니다.
- 목록에 한 번이라도 나온 리소스마다 행 메뉴와 상태 아이콘용 정보를 앱을 끌 때까지 들고 있던 것을 없앴습니다. 리소스 종류마다 하나만 둡니다.
- 편집기(YAML 편집 탭, 파드 affinity·CRD 상세 등)가 연 내용을 닫은 뒤에도 메모리에 남기던 것을 없앴습니다. 편집 탭을 닫거나 상세를 닫으면 그 내용을 버립니다.
- 상세 패널의 메트릭(CPU·메모리 등 그래프)을 패널을 닫은 뒤에도 리소스마다 메모리에 남기던 것을 없앴습니다. 패널을 닫으면 그 메트릭을 버리고, 열려 있는 동안은 지금처럼 1분마다 새로 받습니다.
- 클러스터 요청, 확장 내려받기, 공개 Helm 저장소 목록, 웹 링크 확인이 끝난 뒤에도 시간 제한 타이머가 정해진 시간(최대 10분)까지 남아 있던 것을 없앴습니다. 요청이 끝나면 바로 치웁니다.
- Helm 차트 목록을 처음 열거나 저장소 색인이 바뀐 뒤, 큰 저장소 색인을 읽는 동안 앱 전체(클러스터 화면 포함)가 잠깐 멈추던 것을 줄였습니다. 색인은 별도 스레드에서 읽고, 같은 저장소를 동시에 여러 번 읽지 않습니다.
- 클러스터에 처음 연결할 때 만드는 보안 인증서를 백그라운드에서 만들어, 그동안 앱이 잠깐 멈추지 않습니다.
- 클러스터 리소스를 앱 안에서 만들고 보관하는 비용을 줄였습니다. 리소스가 많을 때 메모리를 덜 쓰고 목록 갱신이 빨라집니다. 확장 기능 개발자께: 리소스 객체의 함수를 객체에서 떼어 따로 넘기던 코드는 이제 동작하지 않습니다. 객체와 함께 부르도록 감싸서 넘겨 주세요.
- 앱을 켤 때 사용자 셸 설정을 읽는 동안 기다리지 않고 창을 바로 띄웁니다. 셸 설정이 무거우면 그만큼 창이 늦게 뜨던 것이 없어졌습니다. 클러스터 연결, Helm, 포트 포워딩처럼 셸 환경(PATH 등)이 필요한 일은 셸 설정을 다 읽은 뒤에 시작합니다.
- 확장 개발자 참고: 확장은 이제 셸 설정을 다 읽기 전에 활성화될 수 있습니다. 셸 설정에서만 PATH 에 더해지는 프로그램을 확장 활성화 순간에 바로 실행하면 찾지 못할 수 있습니다. 셸 설정을 다 읽으면 환경이 채워지므로, 그 뒤에 실행하는 경우에는 영향이 없습니다.
**수정**
- 이벤트가 아주 많이 쌓였을 때 가장 최근 이벤트부터 사라지던 문제를 고쳤습니다. 이제 가장 오래된 이벤트부터 정리합니다.
- 리소스가 아주 많은 클러스터에서, 처음엔 보이던 리소스 일부가 변경을 반영한 뒤 목록에서 사라지던 문제를 고쳤습니다.
- 클러스터에 다시 연결할 때마다 주기적인 연결 확인과 권한 갱신이 한 벌씩 더 늘어나던 문제를 고쳤습니다. 몇 번을 다시 연결해도 확인은 한 번씩만 돌고, 연결에 실패한 뒤 연결을 끊거나 클러스터를 지우면 남은 확인도 함께 멈춥니다.
- 권한이 없거나 사라진 리소스를 5초마다 끝없이 다시 감시하던 문제를 고쳤습니다. 이제 이런 응답을 받으면 감시를 멈춥니다.
- 모든 네임스페이스를 보는 목록 화면을 서비스 상세나 로그 탭과 함께 열면, 목록이 한 네임스페이스의 변화만 실시간으로 반영하던 문제를 고쳤습니다.
- 목록에서 상세를 연 채로 아래로 스크롤해 두면, 목록이 갱신되거나 다른 행을 체크할 때마다 열어 둔 항목 쪽으로 스크롤이 되돌아가던 문제를 고쳤습니다.
- 파드 메뉴에서 로그를 열면, 한 번도 다시 시작하지 않은 컨테이너인데도 "이전 컨테이너를 찾을 수 없다"는 오류가 나고 로그가 보이지 않던 문제를 고쳤습니다.
- 사용자 정의 리소스(CRD)를 지운 뒤 앱이 그 리소스를 계속 등록된 것으로 두던 문제를 고쳤습니다. 같은 이름으로 다시 만들면 새 정의대로 보이고, 지운 리소스의 목록은 메모리에서 버립니다.
- 설정 입력란에 아주 빠르게 입력하면(키를 누르고 있는 반복 입력 등) 중간 글자가 사라지고 잘못된 값이 저장되던 문제를 고쳤습니다.
- 클러스터 인증 프록시가 시작하다 실패하면 연결 화면이 끝없이 기다리던 문제를 고쳤습니다. 이제 바로 실패를 보여 주고 다시 연결할 수 있습니다. 여러 곳에서 동시에 연결을 시작해도 프록시를 하나만 띄워, 끌 수 없는 프록시 프로세스가 남지 않습니다.
- 앱의 상세(debug) 로그에 클러스터 요청의 인증 헤더(토큰), 연결 정보, 요청 본문이 함께 기록될 수 있던 문제를 고쳤습니다. 이제 요청 방식과 주소, 결과만 남깁니다.
- 앱을 시작할 때 가져오는 셸 환경 변수(토큰 같은 값 포함)가 앱 로그 파일에 그대로 기록되던 문제를 고쳤습니다. 이제 출력 크기와 변수 개수만 남깁니다. 이미 쌓인 로그 파일은 그대로 남아 있으니 필요하면 로그 폴더에서 지워 주세요.
